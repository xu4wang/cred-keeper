接口与命令行

只读 REST 接口、Prometheus 指标、用量看板与命令行。

REST 接口

只监听回环地址。对外暴露请经反向代理，并只放行 GET/HEAD。响应里没有 token，也没有脚本输出。

路径说明
GET /healthz存活、版本、账号列表、是否启用告警、keychainGate、机队摘要（未启用为 null）
GET /v1/accounts全部账号：label / labelSource、状态、指纹、AT 与 RT 到期、下次刷新、推迟起点、上次刷新、连续失败次数、用量
GET /v1/accounts/{{id}}单个账号，另带最近 20 条事件
GET /v1/accounts/{{id}}/usage最新用量快照
GET /v1/accounts/{{id}}/usage/history?since=24h用量时间序列；since 支持 30m / 6h / 7d 或 ISO 时间
GET /v1/usage所有账号的用量
GET /v1/events?account=&type=&since=&limit=事件日志（只有退出码和耗时，没有脚本输出）
GET /v1/fleet机队模式：本机发布了哪些号，以及每个镜像的指纹、AT 剩余、来源、最近同步/更新时间、freshness
POST /v1/fleet/sync机队模式：立即拉取所有镜像。请求和响应都不带凭证；只能本机调用
GET /metricsPrometheus 文本：AT 剩余分钟、RT 剩余天数、连续失败、状态、5h/7d 用量、镜像 AT 剩余

账号状态 state

值含义
ok正常
refreshing / retrying刷新中 / 网络失败后等待重试
deadRT 失效（invalid_grant），需要人工重新登录
critical有无法自动判断的 pending 响应或无法识别的刷新响应，需要人工处理
breaker权威副本和发布文件都不可用，已熔断

用量看板

仓库 examples/dashboard/ 是一个静态页面，展示一个或多个实例的全部账号：状态、5h / 7d 用量（含重置时间与预测）、AT 剩余、RT 到期日，以及 7 天曲线。每分钟自动刷新，只调用上面的 GET 接口。

  1. 把 index.html 放到 Web 目录，同目录放 sites.json：[{ "key": "<路径段>", "name": "<显示名>" }]
  2. 同域名下把 /api/<key>/ 转发到各实例，只放行 GET/HEAD（参考 nginx.example.conf）。服务本身不发 CORS 头。

命令行

cred-keeper serve [--config <path>]
cred-keeper status [id]
cred-keeper refresh <id> --force --confirm <id>     # 会轮换 RT，并吊销所有使用方手上的当前 AT
cred-keeper pending <id> apply|discard --confirm <id> [--replace <副本指纹>]
cred-keeper doctor                                    # 连通性、凭证文件、keychain 分裂、脚本、契约、旧 cron
cred-keeper alert-test                                # 发一条测试告警
cred-keeper keychain-sentinel                         # macOS：创建哨兵条目
cred-keeper install-service [--load]                  # macOS LaunchDaemon plist / Linux systemd --user
cred-keeper fleet-keygen <path>                       # 生成机队密钥（不覆盖已有文件）
cred-keeper fleet-sync                                # 让运行中的服务立即同步所有镜像
