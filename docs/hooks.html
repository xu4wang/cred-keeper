脚本与钩子

cred-keeper 与使用方之间唯一的接入点：三类脚本的调用约定。

脚本是 cred-keeper 与使用方之间唯一的接入点。所有脚本都直接执行（不经 shell），各自运行在独立进程组里，超时整组结束。服务的 PATH 只有 node 所在目录加系统目录，所以脚本里请用绝对路径；botmux、lark-cli 这类 node 脚本用 "$NODE" <脚本> 调用。环境变量里从不传 token，需要时自己读文件。

onRefreshed

项目约定
何时执行每次成功刷新（或恢复 pending）并写好文件之后
环境变量CK_ACCOUNT CK_EVENT=refreshed CK_CREDENTIAL_PATH CK_FINGERPRINT CK_AT_EXPIRES_AT CK_RT_EXPIRES_AT
超时 / 重试hookTimeoutSec（默认 60 秒）内重试 1 次；仍失败发 hook_failed critical
典型用途让使用方换上新凭证：例如 botmux suspend --bot <appId>，下一条消息冷启动时复制新凭证

preRefresh

刷新会立刻作废旧 AT，正在用它的请求都会失败（claude 报 provider_authentication_failed，还可能把它自己那份凭证清空）。这个脚本让到期的刷新等到使用方空闲再做。

项目约定
何时执行到期待刷新期间，每次巡检（1 分钟）一次。CLI 强制刷新不执行
环境变量CK_ACCOUNT CK_EVENT=pre_refresh CK_CREDENTIAL_PATH CK_AT_LEFT_MIN
退出码75 = 忙，推迟到下次巡检；0 = 可以刷新；其他退出码 / 超时 / 起不来 → 照常刷新并记 pre_refresh_failed warn：按时刷新比保住一轮对话更重要
上限AT 剩余 ≤ redMin 时不再推迟；连续推迟满 preRefreshMaxDeferMin 也不再推迟。推迟计时只在内存里，重启会重新计时，真正的硬上限是 redMin
事件refresh_deferred（每次推迟只记一次）、refresh_defer_ended（reason：idle / not_due 为 info，floor / max_defer / gate_failed 为 warn）

机队模式下，同一道闸门还会询问其他机器上使用这个号的 bot 是否在忙，规则与上限完全相同，见机队模式 · 查忙。

仓库里的示例（examples/）

脚本用途
on-refreshed-botmux-default.sh共享默认账号：播种各 bot 的凭证副本，然后 botmux suspend all。配了 credentialsSourceDir 的 bot 会被跳过

pre-refresh-botmux.sh用 botmux suspend --dry-run 判断：有会话会被「排队」（正在回复）就返回 75。只读
fleet-botmux-mirror.sh机队镜像的三个钩子共用：按 bots.json 里的 credentialsSourceDir 自动找到使用该号的 bot
