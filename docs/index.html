概览

多账号 Claude OAuth 凭证的刷新、用量监控，以及跨机器共享。

cred-keeper 让一台机器上多个 Claude 账号的 OAuth 凭证一直有效：到期前自动刷新、监控每个账号的 5 小时 / 7 天用量、对外提供只读 REST 接口。开启机队模式后，多台机器还能通过一个 Redis 共享账号，任何机器上的使用方都能用任何一个账号。

它独立运行，不认识 botmux 或任何其他使用方。每次刷新后执行该账号配置的脚本，使用方就通过脚本接入。

它解决什么问题

  • 凭证过期。Claude 的 access token（AT）约 8 小时过期，refresh token（RT）每次刷新都会轮换。多个进程各自刷新，会互相把对方的 RT 作废。cred-keeper 让每个账号只有一个刷新者。
  • 刷新打断正在进行的对话。刷新会立刻作废旧 AT。preRefresh 闸门让刷新等到使用方空闲再做。
  • 撞限流才知道。每个账号的 5h / 7d 用量定时采样、线性外推，快撞了就告警；配套的用量看板一屏看全机队。
  • 账号被机器绑死。机队模式下，账号在哪台机器刷新与哪台机器上的 bot 使用它无关，换号只改使用方的一个配置项。

设计原则

  • 秘密不出门。token 不进命令行参数、环境变量、事件或接口响应，对外只出现 sha256 前 12 位指纹。机队模式下 Redis 里只有密文。
  • 不丢唯一的 RT。刷新响应先原样落盘再解析；任何「可能持有唯一有效 RT」的数据都不会被静默删除。
  • 只读接口。对外只提供 GET（机队模式另有一个不带数据的本机 POST 触发同步）。
  • 与使用方解耦。接入点只有脚本。不配机队段时，机队代码都不会加载。
