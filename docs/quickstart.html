安装与上手

从零装好 cred-keeper，跑起来，再装成开机自启的服务。

运行要求

  • Node.js 24 及以上。直接运行 TypeScript 源码（type stripping），使用内置的 node:sqlite，没有原生模块，也没有构建步骤。
  • macOS 或 Linux。

安装

git clone https://github.com/xu4wang/cred-keeper.git ~/.cred-keeper/app
cd ~/.cred-keeper/app && npm ci --omit=dev

最小配置

写 ~/.cred-keeper/config.json。下面管理一个账号：本机 claude 默认目录里的凭证。

{
  "listen": "127.0.0.1:8790",
  "dataDir": "~/.cred-keeper",
  "accounts": [
    {
      "id": "default",
      "credentialPath": "~/.claude/.credentials.json",
      "onRefreshed": "~/.cred-keeper/hooks/on-refreshed.sh"
    }
  ],
  "alert": { "script": "~/.cred-keeper/hooks/alert.sh", "minLevel": "error", "heartbeat": "09:00" }
}

完整示例见仓库 examples/config.json，每个字段的说明见配置参考。

检查与试跑

./bin/cred-keeper doctor --config ~/.cred-keeper/config.json   # 连通性、凭证文件、脚本、契约
./bin/cred-keeper serve  --config ~/.cred-keeper/config.json   # 前台运行
curl -s 127.0.0.1:8790/v1/accounts                             # 另开终端查看状态
别拿真凭证做实验。复制一份真实凭证去刷新就是一次真刷新：它会轮换 RT，并吊销所有持有者手上的 AT。测试接口只用垃圾 refresh token。

安装为服务（macOS）

推荐以 LaunchDaemon 运行：属于 system 域，UserName 是你本人，并显式设置 HOME、USER、PATH。开机后即使没人登录也会启动，用户级 LaunchAgent 做不到这一点。

cred-keeper keychain-sentinel --config …     # 在普通登录会话里执行一次
cred-keeper install-service --config …       # 生成 <dataDir>/com.cred-keeper.plist，并打印下面的命令
sudo install -o root -g wheel -m 644 <plist> /Library/LaunchDaemons/com.cred-keeper.plist
sudo launchctl bootstrap system /Library/LaunchDaemons/com.cred-keeper.plist
curl -s 127.0.0.1:<port>/healthz              # keychainGate 应为 "active"

Linux 上 install-service 生成 systemd --user 单元。

升级

cd ~/.cred-keeper/app && git pull --ff-only && npm ci --omit=dev
# 重启服务：LaunchDaemon 直接结束进程，KeepAlive 会拉起；LaunchAgent 用
launchctl kickstart -k gui/$(id -u)/com.cred-keeper

配置文件改动不需要重启：mtime 变化或收到 SIGHUP 即热加载（有刷新进行中时推迟到刷新结束）。

从旧 cron 迁移

  1. 选一个刚刷新完的闲时窗口，备份 crontab，删除其中的刷新行和契约审计行。
  2. 该账号配置 legacyLockDir 指向旧锁，使服务与可能还在跑的旧脚本互斥。
  3. cred-keeper doctor 确认 cron 行已删除后，从配置里去掉 legacyLockDir，否则服务在刷新中途被重启留下的旧锁会永远卡住刷新。
